# Фото в PDF

Цель — отдельные страницы в правильном порядке, плотные границы и сохранённые штрихи у краёв. Работай локально с фотографиями. Специальный плагин или MCP для этого процесса не требуется.

## Проверенный способ

1. **Осмотри исходники.** Учитывай EXIF. Проверь порядок по именам/времени и содержанию; время съёмки само по себе не доказывает последовательность. Найди обложку, развороты, переснятые дубли, пустые листы. Яркость не позволяет надёжно отличить бледный чертёж от пустой страницы.
2. **Разметь листы.** `scripts/scan.py prepare` создаёт черновой manifest и контактные листы с контурами. Детектор ищет бумагу как крупную светлую малонасыщенную область (кожа, стол и монитор обычно отсекаются), подгоняет прямые к кромкам каждой страницы отдельно и ставит сгиб разворота по резкому перепаду яркости рядом с тенью корешка. Это начальная гипотеза: `detection` = `contour`, `full-frame-fallback` или с суффиксом `-uncertain` (низкий `gutter_contrast`) требует ручной разметки, остальные — проверки. Осматривай весь кадр: детектор может взять монитор, чек или одну половину разворота. `scan.py inspect` даёт крупные вырезки каждого угла с делениями в долях кадра — по ним правь углы в manifest. Каждый лист получает отдельные четыре угла TL, TR, BR, BL в координатах после EXIF-поворота.
3. **Исправь перспективу.** По умолчанию — одна проективная матрица на лист. Не двигай отдельные строки/столбцы вслед за автоматически найденной кромкой: сетка, текст, пальцы и тени могут быть приняты за край и создать волны во всём листе. Для явно запрошенного полноценного выпрямления изогнутой книжной страницы нужен отдельный проверенный алгоритм и дополнительная проверка геометрии.
4. **Подгони границы.** Предпочтительна плотная обрезка, а не одинаковый большой запас везде. `bleed_px` по умолчанию 0. Добавляй небольшой запас индивидуально, только если за прямой между углами действительно остаётся запись или выгнутый край с информацией. Проверяй верхушки букв, точки над ё/й, даты слева, текст у сгиба и нижние линии чертежей. У сгиба самая тёмная полоса (тень) лежит на одной из страниц, а не на линии сгиба: граница по тени срезает концы строк, писавшихся в корешок. Нижняя строка часто доходит до самой кромки — там граница по медиане кромки, а не плотно. Дополнительную обрезку PDF делай командой `crop`, без повторного растягивания и JPEG-пересжатия.
5. **Сохрани бледные штрихи.** Мягкая коррекция освещения допустима; жёсткая бинаризация может стереть карандаш. Для обложек, фотографий и важных цветов отключай `enhance`. Не дорисовывай буквы, схемы или отсутствующие части кадра генеративной моделью. OCR добавляй только когда он нужен или запрошен.
6. **Проверь итоговый PDF.** Используй доступный навык PDF для создания/проверки, включая предусмотренный им маркер операции. `review` рендерит все страницы и делает контактные листы. Просмотри весь документ, а не только первые страницы; при большом объёме раздай диапазоны страниц параллельным проверяющим и попроси номера страниц — так заодно проверяется порядок. Отметки «возможно срезано» по уменьшенным рендерам часто ложные: сравни это место с исходником (обратная `matrix` из `.scan.json` переводит точку страницы в координаты фото) и правь только подтверждённое. После обрезки перепроверь затронутые страницы; после изменения геометрического алгоритма — весь документ. Число страниц и корректный config не заменяют просмотр.

Для такой оцифровки пользователь предпочитает удалять подтверждённо пустые листы; явный запрос сохранить их имеет приоритет. Дубли исключай после визуальной проверки, не по сходству сетки/почерка. Обложку сохраняй, если нет другой инструкции. Разворот читай слева направо, когда так устроен источник.

## Команды

Путь к скрипту определяй относительно этого навыка. Schema и параметры: [references/commands.md](references/commands.md). Не переноси углы, пути, номера страниц и пропорции из предыдущей тетради.

```bash
python3 <skill>/scripts/scan.py prepare <photos> --work <work> --layout auto
python3 <skill>/scripts/scan.py build <work>/manifest.json --output <work>/draft.pdf
python3 <skill>/scripts/scan.py review <work>/draft.pdf --work <work>/review
```

Зависимости: Pillow, NumPy, OpenCV, ReportLab для фото; pypdfium2 для `crop`; Poppler `pdftoppm` для `review`. Импорты разделены по командам. Проверь доступные интерпретаторы/готовые окружения; при необходимости используй отдельное venv, не меняя глобальный Python. Если OpenCV/NumPy стоят системными пакетами, создавай venv на том же интерпретаторе с `--system-site-packages` (`python3 -m venv`; `uv venv` по умолчанию берёт свой Python и системный cv2 не увидит). Сеть не предполагается обязательной. Не встраивай пути из кэша конкретной машины в навык.

**Пропорции и размер листа.** `aspect: null` оценивается по сторонам контура и под ракурсом может быть смещён на 1–2 %. Для бумаги в клетку измерь физический формат по сетке после чернового `build`: число клеток по ширине и высоте (клетки должны быть квадратными) даёт ширину/высоту в мм; одно значение на всю тетрадь ставь в `aspect`. Чтобы все страницы PDF имели одинаковый физический размер, задай `--width-mm` (или `width_mm` у страницы); иначе размер следует из пикселей и `--dpi` и скачет вместе с расстоянием съёмки.

`build` требует `reviewed: true` у включённых страниц: это отметка проверки разметки агентом, а не дополнительное согласование с пользователем. Не спрашивай разрешение на рутинную обработку уже переданных фотографий.

## Завершение

- Исходные фото не изменяй. Существующий PDF заменяй после проверки новой версии. Сохраняй разметку и параметры для точечных исправлений.
- При повторной правке сначала проверь актуальность файла. Не допускай накопительного JPEG-пересжатия.
- Сообщай результат, число страниц и существенные ограничения исходников. Если часть записи уже вне кадра, укажи это вместо заявления о восстановлении.
- Навык экономит подготовку и повторное написание кода; полностью автоматическое распознавание границ и отмену визуальной проверки он не обещает.
