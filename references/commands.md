# Команды и manifest

`<skill>` — каталог навыка, `<work>` — отдельная рабочая папка.

```bash
python3 <skill>/scripts/scan.py prepare <photos> --work <work> --layout auto
```

Вход — изображения верхнего уровня папки. Имена сортируются естественно: `2` перед `10`. Многостраничные TIFF сначала раздели на кадры. `--layout pages` / `spreads` задают явный тип; `auto` делит широкий контур (отношение сторон > 1,25) только при наличии признаков сгиба: широкой светотени или тонкой устойчивой линии почти по всей высоте листа. Без таких признаков альбомный лист остаётся одной страницей `P`. Проверка выполняется в фиксированном кадре 800×600; порог контраста — 2 уровня синего канала. Текст, внутренние линии таблицы и цветная разлиновка сами по себе не подтверждают сгиб. Это гипотеза: сплошная печатная линия или тень могут имитировать сгиб, а совершенно плоский разворот без видимого сгиба требует `--layout spreads`. Явные `pages` и `spreads` не используют эту проверку.

`--jobs N` задаёт число процессов обработки фото; `--jobs 1` включает последовательный режим. По умолчанию число процессов ограничивается числом доступных ядер и оценкой свободной памяти; при невозможности определить память используется один процесс.

Создаются `manifest.json`, `source-NNN.jpg` с контурами (L красный, R зелёный, P пурпурный) и обзорные `sources-NNN.jpg`. Миниатюры не используются для итогового PDF. Координаты относятся к полному изображению после EXIF.

Детектор:

1. Маска бумаги (насыщенность < 60, при неудаче < 145; яркость > 110), крупнейшая область, четырёхугольник по выпуклой оболочке — черновой контур.
2. В выпрямленной системе координат (черновой контур плюс 6 % с каждой стороны) точки кромки маски притягиваются к самому сильному переходу «бумага → заметно более тёмный фон» в пределах 2 % ширины. Светлые торцы нижних листов и кожа этот переход не дают, там остаётся кромка маски. Через точки проводятся робастные прямые: верх и внешние стороны плотно (90 % кромки снаружи), низ по медиане. Не меньше 30 % точек остаётся в подгонке, поэтому изогнутая кромка аппроксимируется, а не отбрасывается. Если больше 20 % точек какой-либо кромки упираются в край этой системы координат (выгнутая страница больше чернового контура), поиск повторяется с запасом 13 %, затем 20 %. Если сразу внутри найденной точки идёт насыщенная полоса (насыщенность выше бумаги на 80, не меньше 90: цветная обложка со светлым бликом по краю), точка переносится через неё на бумагу.
3. Записи у поля: штрихи пера — тонкие (уже 11 px), темнее бумаги вокруг больше чем на 40 уровней и синее местного оттенка бумаги. Если такие штрихи лежат между плотной прямой и самой внешней прямой бумаги (5 % точек кромки снаружи), кромка сдвигается наружу до них с запасом 4 px, но не дальше чем на 4 % ширины страницы. Сдвинутые кромки перечислены в `margin_ink`. Если запись лежит дальше этого предела, ставится флаг `margin-ink`. Карандаш (серый) этим правилом не ловится.
4. Сгиб разворота ищется внутри подогнанного контура, в центральных 28 % ширины. На синем канале, где чернила и голубая разлиновка заменены фоном, находится самая тёмная прямая линия (допускается наклон до 5 % ширины). Тонкая тетрадь: эта линия и есть сгиб. Глубокая тень (≥ 15 уровней): в трёх полосах по высоте сгиб ставится у основания самого крутого перепада рядом с линией, со стороны тени, на уровне 30 % пикового наклона. Страницы перекрываются на ~0,15 % ширины разворота.
5. Верх у сгиба: у разворота бумага к сгибу прогибается вниз, и прямая верхняя кромка, подобранная вдали от сгиба, оставляет в углу у сгиба клин фона. Если под прямой у сгиба (от 2,4 до ~6 % ширины страницы от сгиба) в большинстве столбцов темнее бумаги того же столбца, прямая поворачивается вокруг внешнего конца вниз до бумаги (не больше 3 % высоты). Поворот отменяется, если между старой и новой прямой есть штрихи пера на бумаге. Повёрнутые кромки перечислены в `gutter_dip` вида `L:12` (сторона и сдвиг в px кадра).

`flags` — признаки неправдоподобной разметки. Такие страницы проверяй первыми, остальные всё равно смотри.

| флаг | смысл |
|---|---|
| `gutter-off-centre` | сгиб дальше 7 % ширины от середины разворота |
| `gutter-ambiguous` | есть второй почти такой же кандидат в сгиб |
| `gutter-bands-disagree` | полосы по высоте не ложатся на одну прямую |
| `one-side-unruled` | одна половина без разлиновки: обложка, фото, вклейка |
| `partner-mismatch` | левая и правая страницы разворота несовместимы по форме или ширине |
| `touches-frame` | угол у края кадра или за ним, либо бумага страницы упирается в край снимка: часть листа может быть вне кадра |
| `margin-ink` | запись у поля лежит дальше 4 % ширины за плотной кромкой: проверь эту кромку |
| `aspect-outlier` | пропорции страницы отличаются от медианы тетради больше чем на 8 % |
| `contour`, `full-frame-fallback` | уточнение не удалось, контур черновой |
| `duplicate` | тот же файл по sha256 уже встречался |

```json
{
  "version": 1,
  "pages": [{
    "id": "0001-L",
    "source": "/absolute/path/photo.jpg",
    "sha256": "hash produced by prepare",
    "quad": [[0.1, 0.05], [0.5, 0.07], [0.49, 0.95], [0.08, 0.94]],
    "aspect": null,
    "bleed_px": 0,
    "enhance": true,
    "include": true,
    "reviewed": false,
    "detection": "edges+gutter",
    "flags": [],
    "gutter_method": "shadow",
    "gutter_depth": 23.4,
    "gutter_ambiguity": 0.42,
    "margin_ink": ["L-left"]
  }]
}
```

- Порядок `pages` — порядок PDF; разворот обычно даёт две записи с одним `source`.
- `quad`: TL, TR, BR, BL, доли ширины/высоты. Умеренный выход за 0–1 допустим для края вне кадра, но не восстанавливает отсутствующий материал.
- `aspect`: физическая ширина/высота листа, если известна; например 210/297 для портретного A4. При `null` пропорции оцениваются по четырём сторонам и при сильном ракурсе приближённые. Не назначай произвольную пропорцию всем документам.
- `bleed_px`: индивидуальный запас за контуром в пикселях выпрямленного изображения, по умолчанию 0.
- `include: false`: исключённая страница; фотография остаётся. Обоснование можно добавить в `note`.
- `sha256`: обнаруживает изменения оригинала после разметки. После замены снимка заново проверь углы и обнови hash.
- `width_mm` (необязательно): физическая ширина страницы в PDF; высота следует из пропорции изображения. Перекрывает `--width-mm`.
- `margin_ink` (необязательно): кромки фотографии, сдвинутые наружу из-за записи у поля, вида `L-left`, `R-bottom`. Поле записывается во все страницы снимка, к странице относятся элементы с её стороной.
- `detection`, `flags`, `gutter_*` (в том числе `gutter_dip`), `margin_ink`, `note`, `duplicate_of` — справочные поля, `build` их не использует.

Ручная правка углов:

```bash
python3 <skill>/scripts/scan.py inspect <work>/manifest.json --work <work>/inspect --ids 0006-L,0006-R
```

Для каждой фотографии — обзор с контурами и вырезки 1:1 вокруг каждого угла (`--half` пикселей в каждую сторону) с делениями в долях ширины/высоты кадра: значения можно сразу переносить в `quad`. Повторный запуск в ту же папку — с `--replace`.

После визуальной проверки исправь углы, порядок и исключения, поставь `reviewed: true` у включённых страниц. Не затирай исправленный manifest повторным `prepare`.

```bash
python3 <skill>/scripts/scan.py build <work>/manifest.json --output <work>/draft.pdf
python3 <skill>/scripts/scan.py review <work>/draft.pdf --work <work>/review --max-edge 1400
```

`build` сохраняет JPEG в `<output-stem>-pages/`, PDF без дополнительного поля и `.scan.json` с параметрами (матрица, пиксели, размер страницы в pt). Один геометрический ресэмплинг; максимальная сторона 2800 px без принудительного увеличения маленьких снимков. `--max-edge` меняет предел; `--quality` (60–100, по умолчанию 95, 4:4:4) — размер файла; `--width-mm` задаёт одинаковую физическую ширину страниц, иначе размер = пиксели / `--dpi`. Ни `--dpi`, ни `--width-mm` не меняют разрешение изображения. ReportLab встраивает JPEG напрямую, ASCII85 отключена.

`review` сохраняет все рендеры, обзоры по шесть страниц и `edges.json`. Для каждой страницы там доля тёмного (V < 120) в полосе 0,6 % у каждого края и доля чернил (насыщенный синий/красный) в полосе 0,4 %. Число страниц выше `--dark-limit` (10 %) или `--ink-limit` (1 %) выводится одной строкой: это слабый намёк, на тетрадях таких страниц большинство; обрезанную запись перечисляет `compare`. Отдельным коротким списком идут полосы: `strip` в `edges.json` для каждой стороны — доля стороны (`share`, %), вдоль которой от края внутрь идёт не бумага (намного темнее бумаги или намного насыщеннее: фон, цветная обложка) глубже `--strip-depth` (0,6 % ширины страницы), и 90-й процентиль этой глубины (`depth`, % ширины). Страницы с `share` больше `--strip-share` (20 %) перечисляются первыми: там контур надо поправить или убедиться, что край бумаги сам неровный (оторванный, выгнутый). Обрезанную запись и сгиб, поставленный внутрь страницы, эта метрика не видит. Существующие результаты не перезаписываются без `--replace`; это защита от затирания, а не требование нового пользовательского согласования.

```bash
python3 <skill>/scripts/scan.py compare <work>/draft.scan.json --work <work>/compare --pages 3,7-9
```

`compare` заново выпрямляет каждую страницу из фото той же матрицей, но с запасом `--margin` (4 %), и рисует красную рамку границы PDF. Всё, что снаружи рамки, обрезано: так видно, срезана ли запись или осталась полоска фона. Если фото изменилось после `build`, команда откажется работать. В `compare.json` для каждой страницы и стороны `cut` — число пикселей штрихов пера на бумаге этого листа снаружи рамки (`null` на стороне сгиба у страниц разворота: там запись соседней страницы). Не считаются длинные прямые (разлиновка, сгиб), бумага, не связанная с самим листом (логотип на столе), окрестность цветной обложки и почти чёрные пятна. Страницы, где на какой-то стороне больше `--cut-limit` (20 px), перечисляются: запись срезана, расширь контур или проверь, не уходит ли она за физический край листа.

## Размер листа по клетке

```bash
python3 <skill>/scripts/scan.py measure <work>/draft-pages --work <work>/measure --cell-mm 5
```

Вход — папка страниц после `build` или PDF (рендерится `pdftoppm` в 200 dpi). Период разлиновки по горизонтали и вертикали считается по автокорреляции профиля красного канала. Берётся первый пик не ниже 60 % от сильнейшего, поэтому гармоники тонких линий не принимаются за клетку. Затем период уточняется по 2–4-кратным пикам. Страница считается клетчатой, если корреляция ≥ `--min-correlation` (0,3) и клетка квадратная в пределах 10 %. Вывод — медианные ширина, высота и `aspect` с разбросом p10–p90 и подсказка `aspect`/`--width-mm`. Для линейки без вертикальных линий оценивается только высота. Если в выводе широкий разброс, значит часть страниц измерена неверно — смотри `measure.json`.

## Оценка детектора по эталону

```bash
python3 <skill>/scripts/scan.py eval <work>/manifest.json --reference <verified-manifest.json> --json <work>/eval.json
```

Страницы сопоставляются по имени файла фотографии и стороне (L, R, P). Ошибка угла — расстояние в пикселях фото в % ширины эталонной страницы, отдельно для внешних углов и углов у сгиба. «Тихая» ошибка — страница без флагов с ошибкой больше `--tolerance` (3 %). Код возврата 1, если тихих ошибок больше `--max-silent` (0). Расхождение набора страниц (например обложка распознана как разворот) печатается отдельно. Эталон — проверенный глазами manifest; держи его вне репозитория навыка, если фото личные.

## Обрезка PDF без пересжатия

План — JSON, ключи — номера страниц с 1, значения — `[left, top, right, bottom]` как доли текущей видимой страницы. Отсутствующие страницы не меняются.

```json
{"1": [0.02, 0.015, 0.98, 0.985], "3": [0.01, 0.0, 0.99, 1.0]}
```

```bash
python3 <skill>/scripts/scan.py crop <input.pdf> --plan <crop.json> --output <work>/cropped.pdf
python3 <skill>/scripts/scan.py review <work>/cropped.pdf --work <work>/crop-review
```

Меняются MediaBox/CropBox/TrimBox/BleedBox/ArtBox. Hash потоков изображений проверяется после сохранения; они не перерисовываются. Сохраняй исходный PDF и план для обратимости. Для ненулевого PDF Rotate сначала нормализуй поворот отдельным проверенным способом: команда отказывается угадывать координаты.
